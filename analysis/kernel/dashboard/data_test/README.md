# Dashboard Query Data Quality Test Suite (`data_test/`)

This directory contains a **per-query data quality test suite** designed to validate the decoded outputs (`.csv` / `.sarif` tables) produced by Linux kernel CodeQL queries before they are imported into the dashboard database.

Complementary to `codeql_db_test/` (which validates the structural health of the raw CodeQL database *before* running queries), `data_test/` validates the *data tables* generated by each query immediately after decoding:

```text
CodeQL Database Creation ──► codeql_db_test/ (Is the database healthy?)
                                   │
                                   ▼
                        CodeQL Query Execution ──► data_test/ (Did each query produce valid data?)
```

---

## 1. Why a Per-Query Output Quality Test Suite?

Even on a healthy CodeQL database, individual queries can silently degrade across kernel releases due to upstream kernel refactoring (such as allocator wrapper renames, `_noprof` macro wrappers, or changes to `file_operations` / syscall entry point definitions):
- **Per-Query Fail-Fast Validation**: Queries can be validated immediately after decoding (`--query <query_name> --results-dir <dir>`). If a foundational query (`functions.ql`, `ops_edges.ql`, `allocs.ql`) produces empty or corrupted output, validation fails immediately rather than waiting for all queries to complete.
- **Graceful Skip for New Query Development**: If `--query <name>` specifies an experimental or newly developed query that does not have a test module mapped in `conftest.py` yet, `data_test` prints `SKIPPED (no test implemented for query '<name>')` and exits with code `0` so new query development is never blocked.
- **Intrinsic & Cross-Table Verification**: Checks verify structural invariants (e.g. `start_line <= end_line`, `sizeMin <= sizeMax`), cross-table agreement (e.g. `ops_targets` and `syscall_node` targets must exist in `function_locations`), and independent BTF ground-truth parity (`allocs.objectSize` vs. BTF `struct_size` from `data/btf_data/extract-btf.py`).

## 2. Test Suite Components

| File | Description |
| :--- | :--- |
| **`conftest.py`** | **Pytest Configuration & Fixtures**. Manages CLI options (`--query`, `--results-dir`, `--btf-db`, and explicit table paths), auto-resolves CSV files from `--results-dir`, loads BTF struct sizes from SQLite (`types` table), and handles exit code `0` skips when a query has no test implemented yet. |
| **`common.py`** | **Shared Validation Utilities**. Provides CSV loading (with automatic `codeql bqrs decode` header detection), Linux kernel relative path canonicalization (`canonical_path`), cross-table agreement metrics (`agreement`), and distribution drift checks (`drift`). |
| **`test_function_locations.py`** | Validates **`functions.ql`** output (`function_locations` table: `file_path`, `function_name`, `start_line`, `end_line`). Serves as the foundational function universe for downstream cross-table checks. |
| **`test_configs.py`** | Validates **`kernel-configs-needed.ql`** output (`configs` table: `config`, `path`, `ifdef`, `endif`, `else_`). Verifies preprocessor block line ordering and core `CONFIG_*` symbol coverage. |
| **`test_ops_targets.py`** | Validates **`ops_edges.ql`** output (`ops_targets` table: indirect dispatch edges through `file_operations`, `inode_operations`, `proto_ops`, etc.). Verifies target population, line ordering, and cross-table resolution against `function_locations`. |
| **`test_allocs.py`** | Validates **`allocs.ql`** output (`allocs` table: 17-column heap allocation sites). Verifies size/flag bound ordering, dynamic sentinel consistency, flexible-array (`isFlexible`) detection, and cross-validation against BTF `struct_size` (`--btf-db`). |
| **`test_syscall_node.py`** | Validates **`syscall-node-pairs.ql` + `syscall-node-locs.ql`** output (`syscall_node` table: syscall reachability graph). Verifies `__do_sys_*` seed coverage, irreflexive reachability, per-syscall reach depth, and cross-table file/function agreement with `function_locations`. |
| **`6.1.111.json`** | **Baseline Distribution Reference**. Stores baseline row counts and dynamic allocation ratios for optional distribution drift checks (`--baseline`). |

## 3. The 5 Table Test Modules (`22 Checks`)

### Module 1: Function Locations (`test_function_locations.py` $\leftarrow$ `functions.ql`)
1. **Total Extracted Function Count**: Must contain `> 10,000` extracted kernel functions (typical full kernel build yields `40,000–200,000+` functions).
2. **Function Line Range Ordering**: `start_line <= end_line` across 100% of extracted function definitions.
3. **Core Kernel Anchor Presence**: Universal built-in kernel entry points (`vfs_read`, `vfs_write`, `__sys_setsockopt`, `schedule`) must be present.

### Module 2: Preprocessor Configurations (`test_configs.py` $\leftarrow$ `kernel-configs-needed.ql`)
4. **Total Preprocessor Block Count**: Must extract `> 1,000` `#ifdef` / `#if defined(CONFIG_*)` blocks.
5. **Preprocessor Block Bound Ordering**: Every block must satisfy `ifdef < endif`, and if `else_ != 0`, must satisfy `ifdef < else_ < endif`.
6. **Core `CONFIG_*` Symbol Coverage**: Fundamental kernel configuration symbols (`CONFIG_NET`, `CONFIG_SMP`, `CONFIG_SECURITY`) must be present.

### Module 3: Operations Table Indirect Dispatch (`test_ops_targets.py` $\leftarrow$ `ops_edges.ql`)
7. **Non-Empty Ops Dispatch Table**: Must extract indirect call edges from kernel operations structures.
8. **Field Population Completeness**: `0` rows with blank `target`; `< 5.0%` rows with blank `parent` struct or `field` name.
9. **Core Operations Table Coverage**: Core dispatch structs (`file_operations`, `inode_operations`) must be represented among parent structs.
10. **Target Function Line Ordering**: `target_start <= target_end` across all resolved function pointer targets.
11. **Cross-Table Function Resolution (`ops_targets` $\leftrightarrow$ `function_locations`)**: `>= 90.0%` of distinct ops target functions must exist in `function_locations`.
12. **Baseline Distribution Stability**: Optional check verifying row count drift stays within bounds relative to `--baseline`.

### Module 4: Heap Allocations (`test_allocs.py` $\leftarrow$ `allocs.ql`)
13. **Non-Empty Allocations Table**: Detects catastrophic allocator wrapper breakage (e.g. `_noprof` rename regressions).
14. **Size & GFP Flag Bound Ordering**: `sizeMin <= sizeMax` and `flagsMin <= flagsMax` across 100% of allocation sites.
15. **Dynamic Size Sentinel Consistency**: Rows with `sizeMin != sizeMax` must match rows marked `sizeVal == "variable"` within tolerance.
16. **Bounded Untyped (`void`) Allocation Share**: Allocations resolving to `void` or empty type must be `< 10.0%` of total allocations.
17. **Flexible Array (`isFlexible`) Detection**: Verifies elastic / flexible-array struct allocations (`isFlexible == "true"`) are detected.
18. **Ground-Truth BTF `objectSize` Parity (`allocs` $\leftrightarrow$ `--btf-db`)**: Cross-validates CodeQL's extracted `objectSize` against BTF `struct_size` from `data/btf_data/extract-btf.py` across all named kernel structs (`>= 90.0%` exact match).
19. **Baseline Distribution Drift**: Optional check verifying total row count and dynamic ratio stability against `--baseline`.

### Module 5: Syscall Reachability Graph (`test_syscall_node.py` $\leftarrow$ `syscall-node-*.ql`)
20. **Syscall Seed Validity & Coverage**: All seeds must start with `__do_sys_`, with `> 300` distinct syscalls represented.
21. **Irreflexive Closure & Plausible Reach Depth**: `syscall != function` (irreflexive edges+), with median reachability `> 500` functions per syscall.
22. **Cross-Table Reachability Agreement (`syscall_node` $\leftrightarrow$ `function_locations`)**: `>= 95.0%` of reached functions and `>= 90.0%` of file locations must match `function_locations`.

## 4. Usage

### 1. Single-Query Validation Mode (`--query`)
```bash
pytest data_test -v -s \
  --query allocs \
  --results-dir /path/to/results_dir \
  --btf-db /path/to/btf.db
```

### 2. Full Results Directory Validation Mode
```bash
pytest data_test -v \
  --results-dir /path/to/results_dir \
  --btf-db /path/to/btf.db \
  [--baseline data_test/6.1.111.json]
```

### 3. Filter Specific Table or Check
```bash
pytest data_test -v -k test_allocs \
  --results-dir /path/to/results_dir \
  --btf-db /path/to/btf.db
```

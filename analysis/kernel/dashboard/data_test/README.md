# Dashboard Query Data Quality Test Suite (`data_test/`)

This directory contains a **per-query and unified SQLite data quality test suite** designed to validate the decoded outputs (`.csv` / `.sarif` tables) and imported SQLite tables produced by all **16 Linux kernel CodeQL queries** in `queries/`.

Complementary to `codeql_db_test/` (which validates the structural health of the raw CodeQL database *before* running queries), `data_test/` validates the *data tables* generated by each query immediately after decoding or importing into `kernel_dashboard-<version>.db`:

```text
CodeQL Database Creation ──► codeql_db_test/ (Is the database healthy?)
                                   │
                                   ▼
                        CodeQL Query Execution ──► data_test/ (Did each query produce valid data?)
```

---

## 1. Why a Per-Query Output Quality Test Suite?

Even on a healthy CodeQL database, individual queries can silently degrade across kernel releases due to upstream kernel refactoring (such as allocator wrapper renames, `_noprof` macro wrappers, or changes to `file_operations` / syscall entry point definitions):
- **Per-Query Fail-Fast Validation**: Queries can be validated immediately after decoding (`--query <query_name> --results-dir <dir>`). If a foundational query (`functions.ql`, `structs.ql`, `ops_edges.ql`, `allocs.ql`) produces empty or corrupted output, validation fails immediately rather than waiting for all queries to complete.
- **Unified SQLite Database Mode (`--sqlite-db`)**: Validates all imported CodeQL tables, `git_log`, `configs`, `kconfig_symbols`, and BTF `types` directly inside a built `kernel_dashboard-<version>.db`.
- **Intrinsic & Cross-Table Verification**: Checks verify structural invariants (e.g. `start_line <= end_line`, `sizeMin <= sizeMax`, zero non-runtime boot/vdso/libstub leakage), cross-table agreement (e.g. `ops_targets`, `syscall_node`, `field_access.enclosing_function`, and `git_log` vs. `function_locations`), and independent BTF ground-truth parity (`allocs.objectSize` and `struct_locations.byte_size` vs. BTF `struct_size`).

## 2. Test Suite Components (`16 Core Queries` $\rightarrow$ `16 Test Modules`)

| File | Validated Query / Table | Key Quality Checks |
| :--- | :--- | :--- |
| **`conftest.py`** | Pytest configuration & fixtures | Manages CLI options (`--query`, `--results-dir`, `--sqlite-db`, `--btf-db`), auto-resolves CSV/SARIF files or SQLite tables, and runs cross-table SQLite invariants. |
| **`common.py`** | Shared validation utilities | CSV/SARIF loading, Linux kernel relative path canonicalization (`canonical_path`), cross-table agreement metrics (`agreement`), and distribution drift checks (`drift`). |
| **`test_functions.py`** | `functions.ql` (`function_locations`) | Function volume (`> 10,000`), `start_line <= end_line`, zero non-runtime files (`arch/*/boot/*`, `*/vdso/*`, `libstub`), core anchor presence (`vfs_read`, `schedule`), and signature-start span accuracy. |
| **`test_structs.py`** | `structs.ql` (`struct_locations`, `struct_fields`) | Distinct struct (`>= 10,000`) and flattened field (`>= 80,000`) volume, zero non-runtime files, anonymous struct/union flattening (`sk_buff.dev`, `sk_buff.cb`, `page.lru`, `inode.i_rdev`), function-pointer field tagging (`file_operations.read`), and `>= 95%` exact `byte_size` parity with BTF `types`. |
| **`test_kernel_configs_needed.py`** | `kernel-configs-needed.ql` (`configs`) | Preprocessor block volume (`> 1,000`), `ifdef < endif` (`ifdef < else_ < endif`), and core `CONFIG_*` symbol coverage (`CONFIG_NET`, `CONFIG_SMP`, `CONFIG_SECURITY`). |
| **`test_ops_edges.py`** | `ops_edges.ql` (`ops_targets`) | Non-empty ops table, field population completeness, core ops table coverage (`file_operations`, `inode_operations`, `proto_ops`, `genl_ops`), and cross-table resolution against `function_locations`. |
| **`test_async_edges.py`** | `async-edges.ql` (`async_edges`) | Coverage across all 7 deferred execution mechanisms (`workqueue`, `timer`, `rcu`, `tasklet`, `irq`, `kthread`, `notifier`), `caller_file`/`callee_file` population, and cross-table resolution against `function_locations`. |
| **`test_allocs.py`** | `allocs.ql` (`allocs`) | Non-empty allocations, `sizeMin <= sizeMax`, `flagsMin <= flagsMax`, dynamic sentinel consistency, flexible-array (`isFlexible`) detection, and `>= 90%` BTF `objectSize` parity. |
| **`test_allocations.py`** | `allocations.ql` (`codeql_allocations`, `codeql_structs`) | Struct-typed heap allocation volume, allocator name normalization, and struct definition resolution. |
| **`test_field_acces_type.py`** | `field-acces-type.ql` (`field_access`) | `read`/`write`/`exec` access classification, zero non-runtime files, anonymous union field resolution (`sk_buff`, `inode`, `page`, `folio`), `enclosing_function` population (`>= 99%`), and `>= 95%` cross-table agreement with `struct_locations` / BTF `types`. |
| **`test_macro_locations.py`** | `macro-locations.ql` (`macro_locations`) | Macro definition volume, valid relative paths, and `start_line <= end_line`. |
| **`test_macro_invocations.py`** | `macro-invocations.ql` (`macroinvocation_locations`) | Macro invocation volume, `CAP_*` invocation coverage, and valid line spans. |
| **`test_syscall_node_pairs.py`** | `syscall-node-pairs.ql` (`syscall_node`) | `__do_sys_*` seed coverage (`> 300` syscalls), irreflexive reachability, and cross-table agreement with `function_locations`. |
| **`test_syscall_node_locs.py`** | `syscall-node-locs.ql` | Location join completeness and line range ordering (`start_line <= end_line`). |
| **`test_entry_node_pairs.py`** | `entry-node-pairs.ql` (`entry_node`) | Non-syscall entry kind coverage (`net_rx`, `netlink`, `ioctl`, `io_uring`, `bpf_entry`, `proc_sysfs`, `kthread`, etc.) and cross-table agreement with `function_locations`. |
| **`test_condition_graph_direct.py`** | `condition-graph-direct.ql` (`conditions`) | Capability check coverage (`capable`, `ns_capable`), `__guarded_span__:<ns_scope>` line intervals, and `__genl_ops_gate__:<ns_scope>` Netlink handler gates. |
| **`test_condition_graph_all.py`** | `condition-graph-all.ql` (`conditions_reachable`) | Inter-procedural guarded reachability volume and valid location strings. |
| **`test_all_calls.py`** | `all-calls.ql` (`locations`, `edges`) | Call-graph node and directed edge volume, valid SARIF threadFlows, and caller/callee location integrity. |

## 3. Usage

### 1. Single-Query Validation Mode (`--query`)
```bash
pytest data_test -v -s \
  --query structs \
  --results-dir /path/to/results_dir \
  --btf-db /path/to/btf.db
```

### 2. Full Results Directory Validation Mode
```bash
pytest data_test -v \
  --results-dir /path/to/results_dir \
  --btf-db /path/to/btf.db \
  [--baseline data_test/6.1.111.json]
```

### 3. Unified SQLite Database Validation Mode (`--sqlite-db`)
```bash
pytest data_test -v \
  --sqlite-db /path/to/kernel_dashboard-6.6.158.db
```
